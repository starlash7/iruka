# Persona management boundary

- Baseline 8ada036 only has GET/POST `/api/me/personas`; PATCH/DELETE remain integration requests.
- Use shared PersonaDto and authenticated API client; never synthesize saved/deleted state on failures.
- Proposed PATCH returns PersonaDto envelope, DELETE returns null envelope. Exact routes and validation are in docs/pivot/handoffs/persona.md.
- Existing chat personaSnapshot stays immutable. FK and chat pin trigger prevent deleting a referenced persona or nulling its chat reference.
- Recommend server-owned soft deletion, excluding deleted personas from list/start; schema decision and implementation remain with integration owner.
- Browser fixture proves UI behavior only. Real PATCH/DELETE CRUD and ownership verification remain pending.
