# iruka 피봇: Conductor 작업 패키지

한국형 AI 캐릭터챗(크랙·에덴챗·베이브챗·제닛 구조) + GIWA 온체인(지갑 로그인, 재화 장부 앵커, 결제 검증)만. NFT·가챠·코인 결제 없음.

## 순서
| Wave | 태스크 | 방식 |
|---|---|---|
| 0 | 01 정리 → 02 스키마·공유계약 | **순차**, 한 번에 하나 |
| 1 | 03 채팅 런타임 API · 04 작품 에디터 · 05 채팅 UI · 06 재화·결제·온체인 · 07 탐색·홈 · 08 시드 작품 이식 | **병렬 6개**, 파일 소유권 안 겹침 |
| 2 | 09 안전·신고·연령 ‖ 10 크리에이터·비용 대시보드 → 11 통합·e2e | 09·10 병렬, 11은 마지막 단독 |

## Conductor에서 돌리는 법
1. 태스크 하나 = 워크스페이스 하나. 각 워크스페이스에 `00-전체-설계.md`와 해당 태스크 문서를 붙여넣어요.
2. 브랜치는 `pivot/<번호>-<이름>`, PR은 draft. main 머지는 직접 해요.
3. 머지 순서: 01 → 02 → (Wave 1: 06 → 03 → 04 → 07 → 05 → 08 권장. 06이 `chargeForTurn` 실구현이라 먼저, 05는 03 이후가 통합이 쉬움) → 09 → 10 → 11.
4. Wave 1 시작 전에 02가 main에 머지돼 있어야 해요(공유 타입·인터페이스 기준점).
5. 마이그레이션 번호 대역: 03=01xx, 04=02xx, 06=03xx, 07=04xx, 08=05xx, 09=06xx, 10=07xx. 겹치면 안 돼요.
6. 공유 파일(`src/shared/**`, `server/core/interfaces.ts`)은 Wave 1에서 아무도 수정하지 않아요. 필요하면 PR에 요청만 적고 Wave 2 전에 한 번 모아서 반영해요.
7. 모든 태스크 공통 금지: main push, 배포, 유료 API 호출, 비밀값 커밋. LLM·PG·본인인증·체인은 mock/anvil로만 테스트해요.
