# 로그인 화면과 새 로컬 환경

승인: 로그인 비교 조사 후 사용자 `ㄱㄱ`, 새 환경 구성 필요(2026-11-03).

- Google 우선, 이메일 OTP, 선택적 지갑. 동일한 로그인 패널을 `/login`과 비로그인 마이페이지에서 사용한다.
- 작품/보관함/제작 진입은 `/login?next=...`로 연결한다. 앱 내부 경로만 복귀하며 작품의 시작 창을 복원한다. URL에는 인증 토큰이나 이메일을 넣지 않는다.
- OTP 전송/확인 중 중복 요청을 막고 재전송 대기, 잘못된 코드/만료 안내, 이메일 변경과 취소를 제공한다. 서버 만료 시간을 추정하지 않는다.
- 새 계정도 서버가 검증한 Privy DID로 기존 프로필 API에 연결한다. 약관 원문/정책 미확정 상태에서 가짜 동의 기록이나 마케팅 체크박스를 만들지 않는다.
- 기존 원본 Iruka 자산을 사용한다. 경쟁 플랫폼 자산은 복사하지 않는다.
- 새 환경은 비밀값 없는 `.env.local` 초기화, 구성 진단, 파일 DB 마이그레이션/재시작 지속성을 검증한다. 실제 Privy 앱 생성과 운영 DB/모델 정책은 별도 외부 입력이 필요하다.
- 실제 모델은 명시적인 서버 구성에서만 연결하고 기본 비활성화한다. 유료 호출/배포/원격 DB 생성은 실행하지 않는다.

검증: 로그인 경로 안전성, 인증 준비/계정 경계, OTP와 실패 복구, 390/768/1440 화면·키보드, 전체 테스트 및 빌드.
