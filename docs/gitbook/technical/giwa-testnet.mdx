## Contract Behavior

`IrukaPackBatch` currently enforces the following flow:

- Commit batch roots, odds, price, and supply before sales begin.
- Reserve one draw index when a collector requests a pull.
- Accept fulfillment only from the configured operator.
- Validate committed seed and inventory proofs before assignment.
- Remove fulfilled inventory positions from the available mapping.

The contract does not represent physical card intake, grading, custody,
ERC-721 ownership, USDC settlement, or shipping.

## Deployment

Use dedicated GIWA Sepolia deployer and Keeper accounts. Never use a wallet
that holds production assets.

```bash
export GIWA_TESTNET_RPC_URL=https://sepolia-rpc.giwa.io
export GIWA_DEPLOYER_PRIVATE_KEY=0x...
export IRUKA_KEEPER_ADDRESS=0x...

forge test
forge script contracts/script/DeployIrukaPackBatch.s.sol:DeployIrukaPackBatch \
  --rpc-url "$GIWA_TESTNET_RPC_URL" \
  --private-key "$GIWA_DEPLOYER_PRIVATE_KEY" \
  --broadcast \
  --verify \
  --verifier blockscout \
  --verifier-url https://sepolia-explorer.giwa.io/api
```

Prepare and commit the 100-position Debut manifest:

```bash
node scripts/giwa/prepare-batch.mjs \
  IRK-GG-2026-001 \
  100 \
  10000000000000 \
  scripts/giwa/debut-odds.json \
  .context/giwa-debut-batch.json \
  debut

node scripts/giwa/commit-batch.mjs .context/giwa-debut-batch.json
```

The public rarity distribution is Common 60, Rare 28, Epic 9, Legendary 2,
and Iruka 1. The private manifest contains committed draw seeds and remains
outside source control under `.context/`.

The Vending panel displays the `0.00001` test ETH charge approved by the
collector's wallet. It is a testnet charge, not canonical USDC settlement.

## Keeper Fulfillment

The browser calls the same-origin Keeper after a request confirms and polls the
same request until `PullFulfilled` is available. A delayed result is retried
without submitting another pull.

Scheduled recovery runs once per minute independently of the collector's
browser. It compares the Debut batch's next requested draw with its next
fulfilled draw and submits at most one missing fulfillment per run. The
contract still rejects duplicate or out-of-order assignment.

The browser and scheduled recovery share an atomic, request-specific Keeper
lease. Only the lease holder can broadcast fulfillment. A stale lease expires
after two minutes so a dropped transaction or interrupted function can be
retried without assigning inventory twice.

The recovery route accepts only Vercel Cron requests authenticated with
`CRON_SECRET`. Debut remains the only committed batch while this direct
request-order recovery is active. A multi-batch launch requires event indexing
that resolves request IDs per batch.

The Keeper uses a dedicated GIWA Sepolia account with fulfillment authority and
minimal test ETH. Its private key and encrypted seed-manifest key are deployment
secrets.

The operator can use the manual recovery script for an existing request:

```bash
node scripts/giwa/fulfill-pull.mjs \
  .context/giwa-debut-batch.json \
  <request-id>
```

This testnet setup is not a production key-management or availability
guarantee.
