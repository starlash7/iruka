> **Status: Live testnet flow** - Sign-in, pack selection, GIWA Sepolia pull
> requests, Keeper fulfillment, and reveal receipts are available. Physical
> custody and commercial settlement are not live.

## 1. Sign In

Collectors can browse without a wallet. Email and Google sign-in create an
Iruka account through Privy. A supported EVM wallet is required only when the
collector submits a GIWA Sepolia test transaction.

Testnet ETH has no monetary value. Iruka does not currently accept commercial
USDC payments.

## 2. Select A Pack

Before a commercial pack opens, its page must publish:

- Batch ID and inventory snapshot time
- Price, total supply, and remaining supply
- Complete eligible card pool
- Individual card and rarity-tier odds
- Estimated value evidence and snapshot time
- Physical redemption eligibility
- GIWA batch commitment

The current Debut batch is a testnet fixture. It proves the commitment and draw
flow; it does not represent sellable physical inventory.

## 3. Review Odds

Odds come from the eligible inventory remaining in a batch. Each card occupies
one inventory position, and a fulfilled position cannot be assigned again.
Material inventory changes require a new batch version and commitment.

See [Packs and Odds](/packs/pack-information) for the current Debut test batch.

## 4. Pull

The collector confirms one `requestPull` transaction. The contract reserves a
draw index and emits `PullRequested`. The Iruka Keeper then submits the
precommitted draw proof in a separate `fulfillPull` transaction.

If fulfillment is delayed, Iruka checks the same request again. It does not
create a second paid request.

## 5. Reveal

Reveal opens only after Iruka reads a confirmed `PullFulfilled` result and
matches the returned inventory commitment to the selected card record. The
receipt links the request, fulfillment, batch, and assigned inventory ID.

The current contract is a testnet commit-reveal implementation. It is not VRF,
commercial settlement, or proof of physical custody.

## 6. Vault

A production card can become `Vaulted` only when its inventory record,
authentication evidence, physical intake, sealed storage record, and ownership
record agree. The interface must not infer custody from a certificate number or
testnet pull alone.

## 7. Sell Or Redeem

Eligible vaulted cards will support either a fixed-price listing or a physical
redemption request. A listed card must be delisted before redemption can lock
the item for shipment.

Fees, payment assets, supported regions, shipping methods, timelines, and loss
or damage procedures will be published before these actions become live.
