# 로그인 화면 비교 — 2026-11-03

사용자 요청: 로그인 화면 → LLM/DB 실제 연결에 앞서 타 플랫폼 로그인 UI를 확인.
버블챗·에덴챗 우선, 뤼튼 공통 인증·제타 보조 비교. 기존 REA 저장소
starlash7/crack의 multi-platform-overview 및 제작 가이드도 읽었으나 과거 기록을
현재 로그인 UI 근거로 사용하지 않았다.

## 확인 방법과 범위

- ego-browser TaskSpace8, 실제 공개 웹 UI와 DOM을 확인했다. 필요한 로그인 경로는
  공개 프런트엔드 번들에서 확인했다. 비밀값·인증 저장소를 읽거나 저장하지 않았다.
- 버블챗·에덴챗에 기존 세션이 있어 사용자가 명시적으로 허용한 뒤 정상 로그아웃했다.
  두 사이트는 **로그아웃 상태로 남아 있다**. 크랙·베이비챗·젠잇 세션은 유지했다.
- 소셜 버튼을 눌러 인증을 진행하거나 비밀번호/이메일을 입력하지 않았다. 인증 메일
  발송·가입·동의 제출·대화 전송·모델 호출·구매·설정 저장은 수행하지 않았다.
- 따라서 첫 화면·입력 화면·복구 화면은 관찰했지만 신규 가입 완료 후의 닉네임/
  동의 단계, OAuth 콜백, OTP 수신, 중복 계정 병합, 실제 DB/LLM 동작은 미검증이다.
- 경쟁사 비주얼은 비교 스크린샷으로만 .context에 보관한다. 코드/프로덕션 자산으로
  복사하지 않으며 계정 화면·대화 원문·이메일·사용자 ID를 보고서에 저장하지 않는다.

## 모바일 관찰

- 버블챗390px: 가로 넘침 없음. 메인 소셜 버튼 높이40px, 기존 계정 링크 약17px.
  Iruka는 기존 디자인 규칙의 44px 터치 영역을 유지한다.
- 에덴챗390px: 이메일 폼은 흰색 둥근 카드로 보이며 뒤로/닫기/입력/비밀번호 전환/
  입장 버튼이 있다. 이메일 폼의 가로 넘침 없음. 소셜 화면은 큰 그림과 버튼으로 구성하고 버튼 높이48px, 이메일 전환 링크32px였다.
- 제타390px: 가로 넘침 없음, 소셜 버튼46px. 뤼튼390px/1440px 공개 폼도 확인했다.
- 체크박스 기반 약관 동의가 첫 화면에 없다는 관찰을 전체 가입 절차에 동의가 없다는
  뜻으로 해석하지 않는다. 키보드/오류/코드 재전송/로그인 복귀 전체 QA는 하지 않았다.

## Iruka 제안 — 아직 구현하지 않음

1. **구성:** 흰색·핑크의 단일 카드. 상단 Iruka 로고와 승인된 원본 비주얼, 짧은 한두 줄
   안내. Google 기본 버튼, 이메일로 계속 보조 버튼, 선택적 지갑은 다른 로그인 방법에 둔다.
2. **이메일:** 현재 제품 규칙대로 OTP. 이메일 입력 → 코드 입력, 주소 수정·재전송·만료·
   오류 상태를 설계한다. 자체 비밀번호 계정을 추가하지 않는다.
3. **흐름:** 로그인/가입은 같은 진입을 사용한다. 닉네임 등 추가 프로필은 최소 입력 또는
   나중에 수정할 수 있게 한다. 탐색은 먼저 허용하고 대화/제작/개인 보관함에서 요청한다.
4. **복귀:** 작품 상세에서 시작한 로그인은 같은 작품·선택한 시작 상황으로 돌아간다.
   취소하면 원래 화면을 유지한다. native dialog와 Privy 포털의 top layer 충돌을 재검증한다.
5. **안내:** 약관·개인정보 안내 링크와 필요한 동의 UI/저장은 별도 확정한다. 타 서비스의
   약관 문구나 자동 동의 방식을 그대로 복사하지 않는다. 최근 로그인 수단은 옵션이다.

## 현재 코드 기반과 다음 확인점

- src/privyConfig.ts: wallet/google/email, 자동 지갑 생성 off. 현재 첫 순서가 wallet이므로
  실제 디자인 작업에서 Google/이메일 중심의 시각적 순서를 조정할 대상이다.
- useReaderLogin / ReaderSession / StartChatAccess: initiating subscriber만 처리, readiness,
  실패/취소, native dialog를 닫은 뒤 SDK 포털 열기 기반이 있다.
- server/core/auth.ts, accounts.ts, profile.ts: 서버 JWT 검증·Privy DID 계정 매핑·프로필 저장.
- server/db/index.ts: PostgreSQL 연결과 로컬 PGlite 지원. 실제 연결 설정을 이번에 읽거나
  실제 DB에 접속·마이그레이션하지 않았다.
- server/models/index.ts: OpenAI 런타임 어댑터가 존재한다. 실제 활성화는 명시적인 모델,
  안전 정책·예약/실차감 정책·한도 설정과 별개다. UI만으로 운영 연동 완료를 표시하지 않는다.
- 다음 순서: 로그인 UI/실제 OAuth·OTP → 동일 DID의 DB 계정·프로필 지속성 → 작품/대화
  소유권·재접속 → 승인된 모델/비용·안전 정책 → 스트리밍·실패/취소·크레딧 정산 검증.
