# 2026-11-03 보안 점검

## 결과

기존에도 인증·소유권·공개 데이터 분리·원자적 크레딧·이미지 검사와 배포용 CSP가 있었다.
이번 점검에서 개발 서버 파일 경계 실패를 합성 canary로 재현했고, 요청 남용 방어,
AI 입력 권한 분리/출력 유출 검사, 캐시 정책 및 의존성 보안 패치를 보완했다.
실제 Privy/운영 DB/유료 모델/배포 검증은 하지 않았다. **출시 보안 완료 판정은 아니다.**

## 확인하고 수정한 항목

속도 제한은 **단일 Node 프로세스의 로컬 보호**다. Origin이 없다는 이유로 인증을 건너뛰지 않는다.
Origin 허용은 `API_ALLOWED_ORIGINS`의 정확한 URL 목록으로 설정하며 wildcard/프록시 헤더를 신뢰하지 않는다.
로컬 Vite 프록시를 통하면 소켓 주소가 동일하여 여러 로컬 사용자가 같은 제한을 공유한다.
운영 프록시/다중 인스턴스에서는 신뢰할 ingress와 공유 저장소 기반 제한을 별도로 구성해야 한다.

## 의존성

npm audit 최초: **34개(높음 25, 중간 9, 치명적 0)**.
호환 범위 패치 후: **30개(높음 23, 중간 7, 치명적 0)**. 운영 의존성만 검사해도 30개다.
이 숫자는 같은 취약 하위 패키지에 연결된 상위 패키지를 포함하며 독립적인 취약점 30개를 의미하지 않는다.

적용한 패치에는 Vite 6.4.5, follow-redirects 1.16.2, fast-copy 3.1.0, Hono 4.13.16,
JOSE 6.2.15, Zod 4 계열의 4.6.7 등이 있다. 메이저 강제 변경이나 기존 선택적 지갑 기능 삭제는 하지 않았다.

잔여 경고의 원인:

- `decode-uri-component` 0.2.2: `query-string`의 `^0.2.2` 의존성. 잘못된 퍼센트 인코딩의 CPU 고갈 경고. 수정 버전 0.5.1은 ESM 전환을 포함해 기존 CommonJS 호출과 호환 검증이 필요하다.
- Zod 3.x: Privy API 및 지갑 SDK가 버전을 고정/제한한다. 컬렉션 검증 시 메모리 고갈 경고. Zod 4 수정 버전을 강제 주입하는 것은 스키마 API의 메이저 변경이다.
- UUID 8/9: MetaMask SDK 의존성. v3/v5/v6의 호출자 제공 buffer 경계 검사 경고. 앱 자체는 해당 API를 사용하지 않으나 SDK 내부 전체 경로가 안전하다고 단정하지 않는다.

현재 서버 소스는 이 세 라이브러리를 직접 호출하지 않는다. 브라우저 인증/지갑 의존성 경로는
남아 있으므로 영향 없음으로 면제하지 않는다. 상위 SDK 수정 또는 호환 대체안 검증을 **출시 전 과제**로 남긴다.

## 기존 방어 확인

- Privy JWT ES256 서명·issuer·audience·exp·DID 검증. 미설정/위조/만료 토큰은 거부한다. 브라우저 세션만으로 서버 권한을 얻지 않는다.
- 대화/메모리/페르소나/폴더/찜/스튜디오/이미지/크레딧은 서버 소유권과 매개변수 SQL을 사용한다. 공개 작품은 중첩 필드 허용 목록으로 투영한다.
- 크레딧 지급/예약/정산/반환은 계정 잠금·트랜잭션·멱등 키를 사용한다. 재시도·동시 요청·실패·취소 회귀가 존재한다.
- PNG는 실제 시그니처/CRC/크기/픽셀 수/압축 해제 상한을 검사하고 메타데이터 제거 후 재압축한다. SVG·APNG는 받지 않는다. 업로드 소유권과 버전별 미디어 접근을 검증한다.
- AI에는 SQL·셸·지갑·임의 네트워크 도구를 제공하지 않는다. 모델/URL/크레딧을 클라이언트가 임의로 확장할 수 없다. provider 요청은 고정 endpoint, redirect 거부, store:false다.
- AI 출력은 완료 후 안전 검사와 등록 이미지/엔딩 투영을 통과해야 공개/저장/정산된다. HTML 실행 렌더러를 사용하지 않는다.
- 배포 설정에는 이미 CSP/HSTS/프레이밍·권한 정책이 있으며 자동 배포는 꺼져 있다. 설정의 존재를 실제 배포 검증으로 보지 않는다.

## 출시 전에 남은 보안 작업

1. 위 SDK 의존성 경고 해소 또는 구체적인 도달 가능성/완화 검증. npm audit 전체가 통과한 상태가 아니다.
2. 실제 모델 안전 서비스, 계정별 일일 사용량·동시 생성·프로젝트 비용 상한, 공유 레이트 리미터·업로드 저장량 제한과 관찰/알림. 지금의 HTTP 제한은 운영 비용 정책을 대체하지 않는다.
3. 실제 모델로 프롬프트 인젝션/다국어·인코딩·의역 추출 평가. 이번 검사는 복사 방어이며 완전한 기밀성 보장이 아니다. API 키·DB 비밀번호·다른 사용자의 데이터는 프롬프트에 넣지 않는다. [OWASP 근거](https://genai.owasp.org/llmrisk/llm022025-sensitive-information-disclosure/).
4. 실제 Privy OAuth/메일·복귀 URL·운영 CSP, 토큰/계정 수명 정책. 앱 등록은 사용자 요청으로 보류한다.
5. 운영 DB 최소 권한·TLS·백업 복원, 키 회전/비밀 관리, 데이터 보존/삭제, 운영 로그의 개인정보 최소화. 원격 인프라는 미구성이다.
6. Git 전체 이력/조직 secret scanning, 지속 의존성 감시. 이번 로컬 검사는 현재 추적 텍스트 파일(2MB 이하)의 고신뢰 패턴만 검사했고 **0건**이었다. 키 유효성이나 모든 형태의 비밀값 부재를 증명하지 않는다.

최종 테스트/빌드 및 전달 기록은 HANDOFF를 따른다. 원본 audit/의존성 경로/합성 재현 로그는
Git 제외 `.context/security-*`에 보관하며 비밀값·실제 사용자 대화는 증거에 넣지 않았다.

전달 검증: Node 24.14.0, `npm ci --ignore-scripts` exit 0,
`npm test` **245 passed / 0 failed / 0 skipped**(49.0초), `npm run build` **exit 0**(5.7초),
`git diff --check` 통과. SDK annotation 및 큰 chunk 경고가 있으며 최대 앱 chunk는 약 2.50MB다.
번들 최적화와 실제 OAuth/모델 동작·운영 인프라 검증은 이번 보안 회귀 결과에 포함하지 않는다.
